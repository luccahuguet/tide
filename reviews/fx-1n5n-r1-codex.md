2. **Blocking — Basename reuse is not SONAME reuse and can grant an unused host ELF file.** `crates/tide-admit/src/invocation/sandbox.rs:445`.

   Suppose an executable first needs /trusted/libalias.so whose DT_SONAME is libshared.so, and subsequently needs libshared.so with RUNPATH=/private. glibc reuses the first object's SONAME; it never opens /private/libshared.so. 3. **Blocking — The new reuse policy selects transitive libraries in the wrong order.** `crates/tide-admit/src/invocation/sandbox.rs:432` (and `:458`).

   pending is a LIFO stack. If the executable needs A then B, and both need libX.so, with A searching /a and B searching /b, this code processes B first, grants /b/libX.so, then reuses it for A. glibc processes A's dependency first and selects /a/libX.so. A valid linked program can consequently fail inside Landlock because its actual library has no grant, or search fallbacks can change its selected library. The new name-reuse rule makes traversal order semantically significant. glibc's [dependency traversal](https://raw.githubusercontent.com/bminor/glibc/release/2.42/master/elf/dl-deps.c) is breadth-first.

   Minimum fix: process pending objects in loader order with a FIFO queue, preserving DT_NEEDED order, together with the corrected identity tracking in finding 2. Add one conflicting-transitive-RUNPATH fixture that checks the selected file and successful sandboxed execution. For inherited RPATH, which the implementation deliberately does not model, fail closed on unsupported resolution rather than claiming general equivalence with ld.so; align README.md:504 accordingly.
