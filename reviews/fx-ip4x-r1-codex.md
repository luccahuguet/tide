## Blocking findings

1. **[P1] The writable grant can include unrelated host files and other runs.** `crates/tide-admit/src/invocation/replay.rs:209`, `crates/tide-admit/src/invocation/sandbox.rs:224` (directory selection at replay.rs:168).

   The policy grants the entire existing `OUT/target/sim`, rather than a fresh directory belonging only to this run. A child reaching raw filesystem operations can read, overwrite, or unlink prior manifests and other active runs' files. More seriously, `create_dir_all` and the ruleset's ordinary `O_PATH` open follow a pre-existing symlink at `OUT/target/sim` or an ancestor. For example, with the default output `.` and `target/sim` pointing to an unrelated user-writable directory, the ruleset grants that directory's contents. A canary there can be read or overwritten while the driver reports `sandbox: full`.

   RUN-3 permits only this run's output directory, and RUN-2 specifies why it must be fresh and outside the candidate tree. The report acknowledges the shared-directory omission, but the symlink-induced grant widening makes it a current confinement defect, including for staged delivery. Minimum fix: create a fresh private run directory under trusted toolchain state, grant only that directory, and publish retained artifacts without following candidate-controlled links. Add a canary check covering a pre-existing output symlink and another run's artifact. Merely documenting the gap does not make `full` truthful.

2. **[P1] Inherited stdout/stderr bypass path confinement.** `crates/tide-admit/src/invocation/replay.rs:246` (command setup at :227-238), `crates/tide-admit/src/invocation/sandbox.rs:398`.

   Only stdin is replaced; `Command::status()` inherits the driver's stdout and stderr. The filter admits unrestricted `read`, `write`, `lseek`, and `ftruncate` on those descriptors. If stdout is redirected to a regular file outside the grant, the child can truncate that file rather than merely emit output. If a launcher supplies a readable/writable file or connected socket as stdout/stderr, the child can read its contents or communicate through that socket without opening a forbidden path or calling `socket`.

   Landlock does not re-check read/write permissions on descriptors opened before enforcement; inherited descriptors retain their prior rights. [Kernel documentation](https://docs.kernel.org/userspace-api/landlock.html#rights-associated-with-file-descriptors). `setsid()` and the ioctl allowlist do not remove this access. RUN-3 explicitly requires harness-owned pipes. Minimum fix: connect both streams to pipes, drain them concurrently in the parent, and route rendered output through the harness's escaping boundary. Add a redirected-file canary that attempts `ftruncate(1, 0)` and checks that existing content survives. Until then, `full` overstates enforcement even on ABI 10.

3. **[P1] Descriptor-cleanup fallback can silently leave host descriptors open.** `crates/tide-admit/src/invocation/sandbox.rs:111-117`.

   On any `close_range` failure, the fallback marks only descriptors below the current soft `RLIMIT_NOFILE`, capped at 1,048,576, and ignores every `fcntl` result. Existing descriptors can be above a subsequently lowered soft limit: a launcher can open non-CLOEXEC fd 4096, lower its soft limit to 1024, then start the driver. If `close_range` is unavailable or denied by an inherited host filter, fd 4096 survives exec. The child's allowed reads/writes then reach that host file outside its Landlock grants. An inherited filter that rejects `F_SETFD` can also make the fallback silently ineffective. A modern Landlock-capable host can therefore still print `full` while leaking descriptors.

   The soft limit constrains new descriptor allocation, not existing descriptors. [Linux resource-limit documentation](https://man7.org/linux/man-pages/man2/getrlimit.2.html). Minimum fix: fail startup when `close_range` fails, or implement and verify cleanup covering all actual inherited descriptors and handle marking errors. The smallest sufficient fix is to remove the unsafe fallback and report its startup failure. Add a focused regression for the high-descriptor/lowered-limit case if fallback compatibility is retained.

4. **[P2] Driver-run simulation tests lose their existing timeout and seed-on-crash diagnostics.** `crates/tide-std/src/sim/runner.rs:20-24`, :189-192; `crates/tide-admit/src/invocation/replay.rs:246`.

   The new context branch bypasses `child(..., TIMEOUT)` and its parent-side deadline/progress monitor, while `start()` suppresses seed records in the replacement execution path. The outer driver only blocks in `process.status()`. A simulation evaluation that loops or deadlocks now hangs `--tide-run-test` indefinitely; a signal termination returns an exit code without the last started seed. The same test previously received the 300-second per-evaluation backstop and crash diagnosis. README.md:378-385 and design/03-authority-concurrency.md:1950-1958 still promise them, and the author explicitly lists this regression as deferred work.

   Running inside the already sandboxed child is the right installation shape, but transferring process ownership must preserve the parent's existing behavior. Minimum fix: move the deadline and seed-progress observation to the driver before removing the inner parent, with a short-timeout regression and a signalled-child regression. This does not require permitting process creation inside the sandbox.
