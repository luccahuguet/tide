harness-owned versioned manifests, macro-supplied origins, strict typed choices,

**Smallest contract:** given a recorded evaluation and the current admitted build inputs, replay either refuses before candidate execution with a named mismatch, or evaluates the same test/input/seed and compares its complete event/output trace and outcome with the recording. A matching identity permits reproduction; it does not prove absence of uncontrolled effects.

## Prior art: what replay actually identifies

“No gate documented” below means the cited interface does not promise Tide's source/dependency/compiler/target/profile/options refusal; it is not a claim about every internal implementation.

| --- | --- |
| FoundationDB | Simulation seed, test/workload configuration and trace logs; an “unseed” checks randomness consistency. Its debugging guide explicitly requires the same OS/build environment, including C++ library choice. This is a prerequisite/warning, not a portable source-hash manifest gate. [Testing](https://github.com/apple/foundationdb/blob/main/documentation/sphinx/source/testing.rst), [debugging](https://github.com/apple/foundationdb/wiki/Debugging-in-FDB). |
| TigerBeetle VOPR | Seed plus Git commit reproduce simulation; the seed determines fault parameters for modeled clock/network/disk behavior. [VOPR](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/internals/vopr.md). |
| madsim | Environment selects seed, count, config-file path and simulated time limit. Optional determinism checking repeats a seed and panics on divergence. No build-identity gate documented; a config **path** alone would not satisfy Tide's inline requirement. [Test API](https://docs.rs/madsim/latest/madsim/attr.test.html). |
| turmoil | Builder records effective seed, epoch, duration and network failure/latency configuration; packet traces are available. Execution is deterministic within its model; no source/build replay gate documented. [Builder](https://docs.rs/turmoil/latest/turmoil/struct.Builder.html), [crate](https://docs.rs/turmoil/latest/turmoil/). |

[How it works](https://antithesis.com/docs/introduction/how_antithesis_works/), [debugging](https://antithesis.com/docs/product/debugging/), [API](https://antithesis.com/docs/reference/rest_api/). |

Reader rejects incompatible trace/protocol versions; CPU features constrain portability. Compiler/profile/source identity is not its replay gate. [Paper](https://arxiv.org/abs/1705.05937), [portability](https://github.com/rr-debugger/rr/wiki/Trace-portability), [reader](https://raw.githubusercontent.com/rr-debugger/rr/master/src/TraceStream.cc). |
| Shuttle | Failure prints an encoded schedule; replay takes that schedule, including a randomness seed. Scheduler consumes recorded task decisions; incomplete schedules require explicit allowance. This is a schedule contract, not source/compiler identity checking. [API](https://docs.rs/shuttle/latest/shuttle/index.html), [replay implementation](https://docs.rs/shuttle-schedulers/0.1.1/src/shuttle_schedulers/replay.rs.html). |
| Loom | Checkpoint contains exploration path, loaded back into the model, with branch/permutation/preemption limits configured separately. It helps isolate a failing iteration. Loader parses the checkpoint; no source/build identity gate appears there. [Builder](https://docs.rs/loom/latest/loom/model/struct.Builder.html), [implementation](https://raw.githubusercontent.com/tokio-rs/loom/master/src/model.rs). |
| Hypothesis | Database persists examples; reproduction blobs serialize internal input choices and include the Hypothesis version. [Reproduction API](https://hypothesis.readthedocs.io/en/latest/database.html), [tutorial](https://hypothesis.readthedocs.io/en/latest/tutorial/replaying-failures.html). |
| proptest | Persists seeds under proptest-regressions and tries them before fresh cases. Changed strategies may produce a different value; persistence deliberately remains useful across changes instead of refusing source mismatches. [Persistence](https://proptest-rs.github.io/proptest/proptest/failure-persistence.html). |

[Testing flags](https://pkg.go.dev/cmd/go#hdr-Testing_flags). |

Rechecking history is distinct from reproducing a live cluster's execution; no universal deterministic replay/build gate is promised by its store API. [Store](https://jepsen-io.github.io/jepsen/jepsen.store.html). |

### Build-identity precedents

| Scheme | Coverage and response to change |
| --- | --- |
| Rust metadata/SVH | `-C metadata` contributes symbol/crate disambiguation; it is not automatically a source digest. SVH incorporates HIR, upstream hashes, filenames and tracked flags. Loader skips wrong SVHs and refuses incompatible compiler metadata. These mechanisms do not specify Tide's complete replay identity. [rustc guide](https://rustc-dev-guide.rust-lang.org/backend/libs-and-metadata.html), [metadata option](https://doc.rust-lang.org/rustc/codegen-options/index.html#metadata). |
| Cargo fingerprints | Track compiler, profile, mode, target/features, extra arguments and dependencies; dep-info also tracks relevant environment. Freshness commonly uses mtimes. Changed fields mark units dirty/rebuild; this is not refusal to replay a recorded program. [Cargo implementation documentation](https://doc.rust-lang.org/stable/nightly-rustc/cargo/compiler/fingerprint/index.html). |
| Reproducible builds | Same source, environment and instructions should produce identical specified artifacts; comparison commonly uses cryptographic hashes. It defines evidence, not an execution refusal policy. [Definition](https://reproducible-builds.org/docs/definition/). |
| Bazel | Actions describe inputs, command, environment and outputs; action cache and content-addressed storage distinguish results. Changed action identity gives a different cache lookup, not a replay warning. Undeclared tools or inputs undermine correctness. [Caching](https://bazel.build/remote/caching), [protocol](https://github.com/bazelbuild/remote-apis/blob/main/build/bazel/remote/execution/v2/remote_execution.proto). |
| Nix | Input-addressed outputs identify the derivation recipe and dependency identities, rather than hashing resulting bytes; content-addressed outputs are distinct. Changed recipes normally yield other addresses, not replay refusal. Fixed-output dependencies deliberately use content identity. [Nix manual source](https://raw.githubusercontent.com/NixOS/nix/master/doc/manual/source/store/derivation/outputs/input-address.md). |

## Design choices and recommendations

1. **Format, location and owner.** Options: macro writes everything; driver writes everything through runtime IPC; or driver owns build identity while trusted std harness writes runs. Recommend the third: macros know test source, the driver knows actual compiler inputs, and std knows evaluation boundaries. Use a versioned JSON object (`tide-replay/1`) with explicit trace/generator versions. JSON matches REPLAY-1's example and existing artifact conventions; TOML adds no value for generated choice tapes. Reuse existing JSON machinery where its contract fits rather than introducing a serializer stack.

   Driver publishes a build receipt paired with the executable, including its byte digest. Supply verified receipt data to the trusted harness; never treat an arbitrary environment string as proof of a binary's provenance. Harness creates an initial manifest **before user evaluation**, then atomically replaces it as inputs/results become available. Keep the initial valid record on abort. Use an operator-owned run directory, with copies under target/sim as RUN-1 describes; current driver forbids build output inside the candidate package. Names include test identity, seed, evaluation ordinal and build identity, with exclusive creation; no overwriting another run. Keep trace bytes inline for a self-contained first format; a sibling .ndjson is a convenience export. This avoids requiring replay to follow manifest-supplied trace paths.

2. **Semantic build identity.** Options: Git commit, executable hash, existing cache key, or a structured content-based receipt. Recommend the receipt. Commit is provenance only; dirty edits must invalidate. Executable hash binds a receipt to an artifact but cannot detect changed current sources by itself. Include: admitted source map; paired library source map; dependency content digests; compiler `-vV` identity; explicit target; debug/release profile; effective edition/test/crate settings, cfg and semantic rustc flags; grants/admission policy identity; tide-admit, tide-std and tide-macros identity; and model/generator versions. Record currently fixed options as fixed values, without exposing new user flags.

   Operator-provided std/dependency artifacts need byte hashes, including the macro shared library and its dependency closure. Today the driver receives binaries, not every dependency's source. Call these **artifact content hashes** honestly; source provenance requires a producer receipt and cannot be inferred from an rlib filename or version. Hash the complete supplied dependency directories conservatively until the driver owns a resolved package graph. This may over-invalidate, but avoids missing a dependency. Retain the current immutable pinned sysroot/C-runtime assumption explicitly; compiler version alone cannot detect an operator replacing those files.

3. **Cheap deterministic computation.** Options: reuse cache digest unchanged; rescan disk afterward; derive a second key from the same snapshot. Recommend the last. invocation.rs already has ordered Sources, length-framed `record`, SHA-256 SourceFileHash, sorted artifact fingerprinting and normalized effective arguments. Its current key includes absolute source/output/tool paths, so **do not** reuse it as portable replay identity. Hash sorted logical relative filenames plus exact snapshot bytes, retaining relative alias/containment structure; use logical artifact-root labels and file digests. Preserve dependency search order where meaningful. Hash effective options with physical output/staging/cache/sysroot locators replaced by roles; retain target/tool identities separately. Never strip arbitrary user strings containing paths.

   Compute once from the same immutable snapshot compiled, before source synthesis; include synthesis-driver/macro identity. Both compile_with_library snapshots must participate: it currently bypasses the normal cache-key path. Recompute current identities before replay, even on a cache hit. Binary digest may differ across relocated rebuilds; compare it with its **current** receipt, not as the semantic equality criterion against the old binary.

4. **Inline inputs and parameter generation.** Options: seed alone, serialized values requiring new bounds, or seed plus existing generator choices. Recommend seed plus a versioned typed choice tape; no Serialize requirement on Arbitrary. fx-m72.2 uses `mix(seed ^ 0x6a09e667f3bcc909)` for parameters; simulator scheduler keeps its independent `seed ^ 0x7469646573636864` stream. Record this derivation version and effective configuration, not host RNG state. Encode u64/u128 values losslessly, e.g. decimal strings; record Kind bounds/width and values, not Debug text.

   Seed regenerates original cases; shrinking changes the tape while retaining seed. Persist the tape **actually consumed**, including synthesized defaults from shrink attempts. Replay consumes it strictly: reject invalid ranges/kinds, exhaustion and leftovers; do not reuse Gen::draw's permissive shrink fallback as replay validation. Reject malformed tapes before candidate execution; dynamic consumption divergence can only be detected while executing and must fail replay. Hypothesis's versioned blobs and proptest's cross-strategy caveat motivate this distinction.

   Store exact test identifier, seed, generator configuration and supported simulated-root configuration inline; empty unsupported input domains stay explicit, not host fallbacks. Do not accept host filenames for injected content. Record injections before application. For this slice there are no external fault/network inputs. Source-defined setup is re-executed from the matching snapshot; future external setup must carry bytes inline. Replay allows no configuration overrides; compare any operator-supplied effective configuration before launch.

   Suggested logical shape: `format`, `build` (component hashes and effective options), `test`, `evaluation`, `seed`, `config`, `inputs` (generator version/stream/choice tape), `roots`, and `result` (completion status, outcome, exact trace, trace hash). Compute a separate run-input digest over canonical build/test/seed/config/input fields. Validate it before launch; changed operator configuration must compare unequal, not silently overwrite recorded configuration. A self-contained manifest's inline configuration is authoritative when no override exists. Checksums detect accidental edits, not malicious rewriting with recomputed digests; no signing/authentication scheme is implied by REPLAY-1/2.

5. **Command and refusal boundary.** Options: seed environment variable, direct test-binary flag, or driver-validated replay. Recommend driver validation. The canonical command is `tide sim --replay <manifest>`, but no tide frontend exists. Implement a labelled partial precursor in the existing driver: `tide-admit --replay <manifest>` with its existing explicit source/build arguments. Print the real, shell-quoted invocation using operator-selected paths, not placeholders or a command that does not exist. The eventual frontend can delegate to this owner. Add public fresh `--seed` selection on the same bounded test-running path; seed and replay are mutually exclusive. Relabel current seed/environment suggestions as **fresh reruns**, never identity-checked replay.

   Parse and validate manifest/version, content digests and supported configuration; snapshot current inputs and compare source/dependencies/compiler/target/profile/options; bind the selected admitted executable to its receipt; only then spawn its exact test. Never run candidate code to query its build identity, and never execute a binary path supplied by the manifest. No force/ignore-mismatch option. Diagnostic names expected/actual component and suggests fresh --seed for changed source. Manifest validation may run trusted compiler code after comparisons; it is not an absolute prohibition on running the driver itself.

6. **Trace and evaluation identity.** Options: compare only two new replays, only hashes, or compare each replay with the original recording. Recommend the last, plus byte equality between the two exported replay traces. Hash the exact fixed-order NDJSON bytes with SHA-256; keep first_difference for precise diagnostics, including missing final newline/extra events. Compare all events, source spans, runnable/chosen task identities and ordered sink stream/message bytes, plus a separate stable outcome signature. Exclude libtest/progress output, wall-clock timing, PIDs and replay diagnostics. An expected panic reproduced correctly remains a failing test, with a separate “reproduced” result.

   Current test/runner.rs self-checks the original evaluation, then reports shrunk parameters without retaining their trace. Keep one manifest's tape, trace and outcome attached to **one evaluation**. Simplest primary artifact is the original failure already self-checked; if printing a minimized replay artifact, reevaluate its final tape and record/check that trace separately. Replay performs no generation search or shrinking. Identical new traces that both differ from the original are failure, not successful replay.

7. **Task-0 span.** Options: continuous track_caller chain or explicit origin. Recommend passing existing macro Config.call Source into the hidden simulator construction path. The current callback is a fn pointer and Gen::simulation calls Root::sim internally; adding track_caller only to __run cannot propagate across this boundary. Rust documents caller loss on fn-pointer coercion. Keep public Root::sim's track_caller behavior; adapt internal span storage minimally to carry explicit file/line/column for macro-created task 0. [Rust reference](https://doc.rust-lang.org/reference/attributes/codegen.html#the-track_caller-attribute).

## Pitfalls and unresolved boundaries

Avoid randomized HashMap/DefaultHasher serialization, filesystem iteration order, native usize encodings and unordered configuration maps. No mtimes, build dates, cache/PID staging names or Git cleanliness as content identity. Build paths and timestamps are known reproducibility hazards. [Paths](https://reproducible-builds.org/docs/build-path/), [timestamps](https://reproducible-builds.org/docs/timestamps/).

The compiler already clears environment; runtime children currently inherit it. Clear runtime environment and supply only explicit harness controls. Simulation environment is inline data, not the host environment; do not dump secrets into a manifest. Normalize source spans through stable compiler path remapping, including macro Config.call and task-0 origin; do not rewrite arbitrary sink messages. Absolute **simulated** paths such as `/` are valid; absolute host paths are locators outside replay identity, never instructions to load inputs from disk.

Artifact byte hashes are intentionally conservative: rebuilding trusted std/macros at another path may change embedded paths and therefore refuse replay, even with equivalent source. Path-independent candidate-source hashing does not by itself establish portable toolchain artifacts. Use identical pinned trusted artifacts initially; do not promise cross-machine replay until that is independently demonstrated. A semantic identity is an equality contract over declared inputs, not a decision procedure for program equivalence.

REPLAY-1 does not specify plain-test association, multiple Root::sim calls, retention, schema evolution, or partial manifests. Recommend driver execution context identifying one exact test, with ordered root-run ordinals recorded at Root::sim boundaries. A plain test replay reruns that exact test and verifies the ordered roots/seeds; it must not silently replace source-written seeds. Direct binary execution without driver context has no verified manifest guarantee. Preserve initial manifests on signal/timeout and distinguish incomplete trace from complete reproduction; stack-exhaustion depth is expressly outside determinism in PANIC-1. These plumbing details must be settled before implementation, without restricting existing sequential Root::sim use.

**Change reach for the implementer:** invocation.rs and its paired-library/cache/publication paths; driver CLI/help and build tests; trusted sim and shared property evaluation lifecycle; Gen choice validation; macro-generated origin metadata; root/scheduler span plumbing; runtime regression fixtures; and current-support documentation. Keep compile-time conformance signatures synchronized where hidden/public surface changes reach the stub. The stub cannot establish replay execution: conformance/README explicitly assigns runtime proof to production driver tests. No authority-diff or D11 behavior-diff implementation belongs here.

## Cheapest falsifiers

| Recommendation | Smallest meaningful falsifier for implementer |
| --- | --- |
| Format/lifecycle | Round-trip one manifest containing quotes, control bytes and maximal integers; reject duplicate keys/unknown version/truncation. Abort immediately after start: valid initial manifest survives; concurrent identical test names never overwrite. |
| Identity/snapshot | Table-driven receipt comparisons change source, paired library, compiler, target, profile, option, dependency, std and macro independently. Each refuses with a spawn sentinel untouched. Same-length dirty edit with preserved mtime still refuses. |
| Deterministic hashing | Same snapshot/artifacts under two roots and shuffled enumeration yields same identity; changed relative filename/alias or semantic option differs. Rebuild/cache-hit paths publish equivalent receipts. |
| Inputs | Parameterized Vec<u16> failure: the original tape replays with unchanged simulator seed and exact associated trace (minimized inputs are reported separately, per the adopted decision); tampered configuration refuses. Invalid/extra/missing choices fail strict replay. No serialization trait added to test parameters. |
| CLI | Execute the printed command from a directory containing spaces/quotes; get one exact test/evaluation. Wrong current source refuses before process creation; fresh --seed runs changed source; combining modes errors. |
| Trace proof | Scheduling-dependent counter witness: original versus replay A versus replay B byte-identical, including sink order and outcome. Mutate one sink/event/newline/outcome: replay comparison fails at the first difference. |
| Origin/ordinary tests | Driver-built macro test task-0 exit names the user's file/line; plain Root::sim retains caller location. A plain test with two sequential roots replays both, ordered. |
