# Public Name Review And Decision

This document records the naming exploration that replaced the earlier working name and ultimately selected **Ferox** as the public language name.

This is **not legal clearance**.

Review date:

* March 8, 2026

## Final Decision

Selected public identity:

* language name: **Ferox**
* CLI binary: `ferox`
* source file extension: `.ferox`

Decision note:

* this final choice was made after the earlier 4-letter-only exploration documented below
* the project later evaluated `Orbis` and rejected it after name-specific trademark and software-brand review
* the remaining candidate notes are kept as historical screening context, not as the current recommendation

## Earlier Constraint

* public language name should be **4 letters or fewer**

## Screening Summary

Current conclusion:

* the 4-letter limit makes clean naming materially harder because exact-match collisions rise sharply
* no candidate below should be treated as legally cleared without attorney review
* `Nyrn` is the strongest current replacement public-name candidate from this first-pass screen

Current interpretation at that stage:

* keep the earlier working name as an internal codename until the public rename is finalized
* treat `Nyrn` as the leading public-name candidate
* keep domain review and final legal review as explicit follow-up gates

## Recommended Candidate

### `Nyrn`

Why it currently leads:

* first-pass public web searching did **not** surface an obvious exact-match software company, app, or developer-tool brand using `Nyrn`
* first-pass trademark searching through public secondary search surfaces did **not** surface an obvious exact-match U.S. mark
* the name is short, visually distinct, and does not read like a generic English word

Risks:

* pronunciation is not self-evident on first read
* some non-software music/artist usage exists
* this is an inference from the sources searched, not proof of clearance

Sources checked:

* Apple Music artist page: https://music.apple.com/kr/artist/nyrn/1513400339
* USPTO trademark search entry point: https://www.uspto.gov/trademarks/search
* Justia trademarks entry point: https://trademarks.justia.com/

## Rejected Or Weaker Candidates

### `Oryn`

Why it was rejected:

* heavily crowded in active software branding
* multiple active apps and software products already use the exact word

Sources:

* https://oryn.io/
* https://useoryn.com/
* https://apps.apple.com/us/app/audio-to-text-converter-oryn/id6756976491

### `Aryn`

Why it was rejected:

* already active in AI/software branding
* exact-match company and documentation footprint is too strong

Sources:

* https://www.aryn.ai/
* https://docs.aryn.ai/introduction

### `Yeti`

Why it was rejected:

* `YETI` is already a strong registered U.S. trademark with major brand recognition
* active software-company and software-product usage already exists under the exact word
* even apart from strict product-category overlap, the mark is too crowded and too famous to treat as a clean language brand

Sources:

* https://trademarks.justia.com/879/83/yeti-87983351.html
* https://www.yeti.co/
* https://www.yetisoftware.com/
* https://yetirocks.com/

### `Ox`

Why it was rejected:

* `Ox` is already the name of an existing programming language
* the exact word is heavily crowded across software libraries, developer tooling, and U.S. trademark records
* at 2 letters, it is also weak for searchability and brand ownership

Sources:

* https://en.wikipedia.org/wiki/Ox_%28programming_language%29
* https://github.com/wevm/ox
* https://trademarks.justia.com/977/61/ox-97761378.html
* https://trademarks.justia.com/884/38/ox-88438033.html

### `Tardigrade` with `tardi` as the binary

Why it was rejected:

* `TARDIGRADE` is already a registered U.S. software trademark owned by Storj Labs Inc.
* `Tardigrade` is already active in software-company branding, so the long-form name is not clean even apart from the trademark issue
* `tardi` also has active software/app usage, including an AI infrastructure brand and a current mobile app, so the binary name is not clean either
* together, this creates collision risk on both the product name and the CLI command

Sources:

* https://trademarks.justia.com/881/26/tardigrade-88126930.html
* https://tardigradetechnology.com/
* https://tardi.ai/
* https://apps.apple.com/uy/app/tardi/id6753170026

### `Varn`

Why it was rejected:

* active app branding already exists under the exact word
* additional software branding is visible under the same exact name

Sources:

* https://apps.apple.com/us/app/varn/id6739300797
* https://www.varncore.com/

### `Veyr`

Why it was rejected:

* active consumer software/app use already exists under the exact word

Sources:

* https://apps.apple.com/us/app/veyr-fitness-everywhere/id6756798399

### `Norl`

Why it was rejected:

* already used by a published CLI/tooling package
* this is too close to the target category for a programming language

Sources:

* https://npm.io/package/norl

### `Zyrn`

Why it was not selected:

* lower conflict than many other short candidates
* still has existing exact-match developer branding, which weakens it as a clean language identity

Sources:

* https://zyrn.dev/
* https://linktr.ee/zyrn

### `Kyrn`

Why it was not selected:

* software conflict looked lower than many alternatives
* exact public-name noise still exists, including `KYRN` radio identity and music usage
* weaker than `Nyrn` on cleanliness

Sources:

* https://radioinsight.com/headlines/298033/santa-gets-stuck-in-socorros-mine/
* https://soundcloud.com/kyyyrn

## Practical Recommendation

For current planning at that stage:

* use `Nyrn` as the leading public-name candidate in future naming discussions
* do not publicly rebrand until domain review and legal review are complete
* keep evaluating whether the pronunciation cost of `Nyrn` is acceptable for a language and CLI brand

This recommendation is retained as historical context only.

The final public naming decision for the project is:

* language name: **Ferox**
* CLI binary: `ferox`
* source file extension: `.ferox`

## Scope Limits

This review does **not** include:

* attorney-led trademark clearance
* full common-law searching
* domain acquisition or registrar analysis
* exhaustive package-registry searching across every ecosystem
